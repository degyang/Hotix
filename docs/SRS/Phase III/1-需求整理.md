## 我现在对你们 DSL 的整体理解

你们这套规则并不是一堆散 YAML，而是一个相当清晰的分层流水线：

```text
raw market data
→ features
→ states
→ patterns / transitions
→ pair_features
→ pair_states
→ relation_tags
→ regimes
→ contexts
→ salience / market summary
```

这条链条在 DSL 里已经基本齐了：

* `features.yaml` 定义原始派生特征，比如收益率、均线、量能比、广度、ATR、突破/跌破等。
* `states.yaml` 把连续特征离散成 `trend_state / position_state / volume_state / breadth_state / volatility_state`。
* `patterns.yaml` 在单资产层识别结构事件，比如“低位放量修复”“高位放量分歧”“放量下跌”“指数上行但跟随不足”。
* `transitions.yaml` 负责状态迁移标记，比如“趋势转上/转下”“量能跳升”“广度恶化”。
* `pair_features.yaml` 和 `pair_states.yaml` 负责风格/结构对比，抽出相对强弱、持续性、确认度。
* `relation_tags.yaml` 再把 pair-level 的结论提升成 market-level 的结构标签，比如“成长风格占优”“权重大盘主导”“小票情绪回暖”。
* `regimes.yaml` 用 relation tags 和关键指数状态判断市场处于“权重防守市 / 成长进攻市 / 结构分裂市 / 混沌市”。
* `contexts.yaml` 再把 regime 翻译成 `Offense / Caution / Defense / Cash`，并给出允许风格、禁止风格和风险预算。
* `salience.yaml` 则定义显著性评分，把 pattern / extreme state / transition 提升为 positive / negative / warning / transition 这几个桶。

所以，我现在会重新定义你们的系统：

> **这不是“规则拼装”，而是一个 declarative market inference engine。**

## 这套 DSL 目前最强的地方

### 1. 分层非常干净

你们把“特征计算”和“状态判断”分开了，把“单体判断”和“pair 判断”也分开了，再把“市场结构”和“交易上下文”分开。这个边界感非常好。

这意味着后面要扩展时，不需要推翻原有规则，只要在相应层补 DSL。

### 2. 已经天然支持 trace

因为每层都是显式规则，`today.json` 里也已经把 trace 打出来了，所以这套东西天然适合：

* 回溯为什么判成这样
* 调整单条规则的权重/阈值
* 做 rule attribution

这一点非常适合你后面做 rule review。

### 3. context 层已经带 risk budget

这点很关键。`contexts.yaml` 不只是标签，还把 `risk_budget` 绑定在 `Offense / Caution / Defense / Cash` 上了。

这说明你们 DSL 不是纯分析 DSL，而已经开始接近 policy DSL。

### 4. relation_tags 设计是对的

你们没有直接从 pair 跳 context，而是先经过 `relation_tags` 这个中介层。

这是好设计，因为它把“局部关系”提升成“市场语言”。以后要加新的风格关系，也有落点。

## 这套 DSL 目前的真实边界

虽然整体很强，但我现在也能更准确地看到它目前**做到哪、没做到哪**。

### 1. 它现在本质上还是“市场推断 DSL”

它能做：

* 描述市场
* 识别结构
* 判断环境
* 给出风格级风险预算

但它还**没有正式进入“策略执行 DSL”**。

也就是说，当前 DSL 的终点是：

> `market_context = Cash / Offense / ...`

而不是：

> `breakout = forbidden`
> `pullback_continuation = allowed_small`
> `reversal_probe = disallowed`

这就是为什么你现在系统已经很强，但我之前一直说“还差策略权限矩阵”。

### 2. context 是风格级，不是 setup 级

`contexts.yaml` 里的 `allowed_styles / disallowed_styles` 还是中文风格短语，比如“趋势跟随”“高弹性进攻”“观察”“等待”。

这适合人看，但对真正执行层还不够硬。
下一步如果要驱动更具体的操作系统，需要把 style 再细分成 strategy/setup 层。

### 3. conflict resolution 还没独立成 DSL

当前冲突处理其实是“隐含在 regimes + contexts 打分逻辑里”的。
比如 `cash` 因为“混沌市”“relation_tags 为空”而赢得更高分。

这没问题，但它还不是显式的：

* 谁压过谁
* 什么属于 override
* 什么属于 veto
* runner-up 和 final winner 的裁决依据是什么

也就是说，你们现在有 **score aggregation**，但还没有完整的 **conflict policy**。

### 4. salience 还是 asset-centric，不完全是 market-centric

`sali​ence.yaml` 主要基于单资产的 pattern/state/transition 来打分。
这意味着 market-level 的 warning cluster、conflict cluster、regime shift pressure 还没有独立 DSL。

所以才会出现你前面那份 `today.json` 里“很多指数有风险特征，但 market top_warning 仍为空”的现象。

## 我建议的下一步，不是直接推进“完整决策层”，而是补 3 类 DSL

### 第一类：Policy DSL

这是最该补的。

你们现在有 `contexts.yaml`，但还需要一个新层，比如：

```yaml
dsl_type: policies

policies:
  - id: pol_breakout_in_offense
    when: "market.market_context.label == 'Offense'"
    set:
      breakout: allowed
      breakout_size: normal

  - id: pol_breakout_in_cash
    when: "market.market_context.label == 'Cash'"
    set:
      breakout: forbidden
```

这个 DSL 的作用是把：

* context
* regime
* relation_tags
* warning/negative salience

翻译成**具体 setup 权限**。

也就是说，从现在的：

* “允许趋势跟随”

变成：

* “20 日突破追涨：禁止”
* “强势回踩承接：允许小仓”
* “低位修复试错：仅限 1 笔试单”

### 第二类：Conflict DSL

显式写冲突裁决。

比如：

```yaml
dsl_type: conflicts

conflicts:
  - id: cf_breadth_vs_structure
    when: "len(market.top_positive) > 0 and market.market_regime.label == '混沌市'"
    explain: "局部正向信号存在，但不足以形成结构主线"
    override:
      context_bias: cash
```

再比如：

```yaml
  - id: cf_positive_but_unconfirmed
    when: "'成长风格占优' not in market.relation_tags and len(market.top_positive) > 0"
    explain: "正向信号未获结构确认"
    effect:
      reduce_confidence: 0.15
      block_context_upgrade: true
```

这样你们的“runner-up 为什么输了”就能直接从 DSL 里读出来。

### 第三类：State Machine DSL

现在 `transitions.yaml` 还只是单资产转移标签。
后面应该补 market/context 的状态机，比如：

```yaml
dsl_type: context_transitions

transitions:
  - id: ctx_cash_to_caution
    when: "prev.market_context.label == 'Cash' and len(market.top_positive) > 0 and len(market.relation_tags) > 0"
    add_tag: 现金期尝试修复

  - id: ctx_caution_to_offense
    when: "prev.market_context.label == 'Caution' and market.market_regime.label == '成长进攻市'"
    add_tag: 进攻环境确认
```

这会把系统从“每日独立判分器”升级成“连续市场状态机”。
